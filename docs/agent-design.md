# pupu 本地决策 Agent 设计方案

状态：首个实验原型已实现，完整方案尚未验收。日期：2026-10-10。

### main 分支：插件功能迁移与单窗口工作台

桌面默认入口已改为复用插件的动态、视频、文章编辑器及平台选择/结果界面。
平台执行页面使用同一个 BrowserWindow 内的 WebContentsView 标签；批量创建和填写不会切换前台，
需要登录或人工处理时由用户选择标签，不为每个平台弹独立窗口。
Chromium API 兼容层只向本地工作台暴露固定 IPC；平台页面无 Node、无 preload 桥接。
平台适配器作为完整模块在 isolated world 运行，小红书图文沿用 CDP closed-shadow 工具和全文回读。
图片/视频/封面通过分块传输和随机标识的本地素材协议跨页面使用，不把工作台 `blob:` URL 直接交给平台。

此迁移路径不依赖大模型。原 Agent 通过 `--agent` 单独进入，模型仍只辅助选择标题字段，
明确且唯一的标题字段直接走规则；登录判断、上传、提交和成功回执不是模型负责。
普通适配器执行结束不等于发布成功，自动模式标记待确认；可能已有提交的页面不允许重载重发。
自动化验证已覆盖真实 Electron 界面按钮、后台多标签、素材传输、Markdown 导入、
PPTX/PDF 真实转图以及小红书模拟单次提交。全平台真实账号发布仍未验收。
本次仅提交源码，v0.3.0 已发布安装包未被替换。

### 独立 Agent 试点交互与自动发布（v0.3.0 / --agent）

用户试用反馈指出“字段观察验证台”不等于可用产品。桌面版现改为内容编辑器 + 平台/Agent 执行面板，
默认不暴露候选 JSON、观察按钮或模型安装步骤。点击自动发布后通过原生对话框授权本次任务，
控制器依次准备图文入口、上传素材、等待编辑器、规则定位标题（有歧义时才调用模型）、填写回读、核对文字、
点击唯一且可用的发布按钮一次，最后等待明确成功提示。登录、验证码、入口歧义或结果未知均显式暂停。
用户仍需在平台窗口确认账号；不读取/继承浏览器 Cookie。

新增提交工具是对原首期“不自动提交”范围的明确扩展，**仅适用于桌面显式授权任务**，
不是模型任意点击能力；扩展中的原 Agent 试点仍不自动提交。
提交尝试在调用前记录，页面导航和超时不能触发自动重发；停止也不能撤销已有提交。
普通与 open/closed shadow DOM 由 Chromium CDP 在无 Node 权限的 isolated world 中执行同一受控工具；
不依赖修改平台 attachShadow，也不向模型提供调试命令或代码生成权限。
iframe、平台验证码与未知页面仍需人工处理。

本地真实模型验收扩展为：closed shadow 编辑器、原生文件输入上传、文字回读、
自动点击一次模拟发布、收到成功回执、重复任务被拒绝、以及工作台按钮到 IPC 到工具的完整交互链路。
真实小红书账号端到端仍待用户登录后的验证，不能用本地演示替代该验收。
后续实测已复现真实平台三个“上传图文”节点，其中两个是屏幕外/近透明副本，
修复后通过同一真实页面的入口操作、图片上传、标题正文填写和延迟回读；发布入口可用。
真实发布未执行，因此成功回执与实际内容发布仍未验收，不应以模拟成功替代。
导航取消逻辑已在真实已登录平台验证：实际点击视频 tab 后再切图文，
从 `target=video&from=tab_switch` 导航至 `target=image&from=tab_switch` 时准备任务不中止。
准备阶段仅允许同源同编辑路径的参数切换，等待加载后重新观察；填写阶段导航仍停止任务。
导航本身不被当作未登录证据。本地模型辅助登录状态判断尚未接入，
不以模型结论替代字段核验或发布授权。
以下首期设计章节保留作为扩展原型的范围基线，不表示桌面新版仍禁止授权自动提交。

## 1. 目标与结论

在保留现有浏览器扩展的前提下，引入本地决策模块，降低平台页面改版导致的适配维护成本。借鉴 Jev 的有限选项决策思路，而不是复制其未公开的模型内部架构。

推荐首期形态：

> Chrome 扩展 + 本机 Ollama + 受控语义定位，仅在既有定位失败时介入；不增加 Agent 自动提交能力。

首期选择小红书图文的标题字段作为切口。目标不是支持任意页面，而是在编辑页已打开、上传已完成、账号已登录的条件下，从可见候选中识别标题框，填写并核验。现有规则决定是否需要标题；规则要求跳过标题时，不调用模型。

### 做什么

- 选择一个正确的标题字段，或明确返回 `none`。
- 页面变化时重新观察，拒绝失效的元素引用。
- 通过本地模型决策，不向外部服务传送页面或发布内容。
- 提供进度、停止、失败原因与手动接管。
- 用固定测试集衡量改版适应能力、耗时和资源开销。

### 不做什么

- 不同时重写所有平台适配器。
- 不提供任意 JavaScript、Shell、Cookie 读取或任意网络请求工具。
- 不处理验证码，不绕过平台权限、风控或服务条款。
- 不承诺模型正确率、置信度校准、闭源 Jev 等价能力。
- 不在首期引入截图定位、文案改写、模型微调、手机本地推理或云端任务服务。

前置检查必须覆盖真实注入，而不只是辅助函数单测：

1. 验证并消除试点适配器的闭包依赖问题。
2. 平台加载等待有超时、关闭和导航处理，避免模型流程尚未开始就永久挂起。
3. 模型决策期间平台任务加锁，用户重试不能与旧任务同时填写。
4. 对试点任务使用新的明确结果，不能将无匹配或未核验的正常返回记为已填充。

这些改造限定在试点调用链，不顺带修改所有平台。

## 3. 架构与执行时序

```text
现有小红书填写流程
  |
  +-- 明确定位成功 --> 确定性填写 --> 回读核验
  |
  +-- 定位失败/存在歧义
        |
        v
    页面观察器 --> 有限候选问题 --> 本地决策 Provider
        ^                               |
        |                               v
    重新观察 <-- 失效引用 <-- 策略校验 <-- 决策结果
                                        |
                                        v
                                  受控填写工具
                                        |
                                        v
                                    回读核验
                                        |
                                        v
                            预览/手动接管；不自动提交
```

职责分离：

- **观察器**：从指定标签页、文档和 frame 读取可见候选，维护临时 DOM 引用。
- **决策 Provider**：只选择当前候选 ID 或 `none`，不得生成代码。
- **控制器**：控制预算、锁、取消、重观察与结果转移。
- **执行工具**：再次验证目标，使用已支持的填写方式，不让模型决定文案。
- **核验器**：回读字段与预期值比较，识别异步重渲染导致的回退。
- **界面**：解释本地模型用途，显示状态，允许停止和手动处理。

首期采用一次一决策的控制循环，不建立通用多 Agent 编排框架。

## 4. Jev 风格的决策接口

以下是拟议契约，不是现有代码。

```ts
type CandidateId = string;

interface FieldCandidate {
  id: CandidateId;
  kind: "input" | "textarea" | "contenteditable";
  label: string;
  placeholder: string;
  nearbyText: string;
  visible: boolean;
  enabled: boolean;
  editable: boolean;
}

interface FieldObservation {
  observationId: string;
  documentId: string;
  frameId: number;
  platform: "rednote";
  pageKind: "editor" | "login" | "unknown";
  candidates: FieldCandidate[];
}

interface SelectTitleRequest {
  observation: FieldObservation;
  field: "title";
}

type SelectTitleResult =
  | { status: "selected"; observationId: string; candidateId: CandidateId }
  | { status: "no_match"; observationId: string }
  | { status: "failed"; code: string; message: string };
```

对模型使用动态枚举：所有当前候选 ID，加上保留值 `none`。引用 ID 使用受控前缀，与保留值不冲突。模型只返回选择值；Provider 验证之后绑定原始 `observationId`，不要求模型自行复制该 ID。

- 输出必须符合 Schema，且 ID 必须属于候选集合。
- 无候选时不请求模型，直接 `no_match`。
- 非法输出是失败，不能默认取第一个候选。
- 模型请求不得包含标题正文、素材、账号名、Cookie、令牌或字段当前值。
- 页面标签是待判断的数据，不是可遵循的指令。
- 首期没有自报 `confidence` 字段；未来若增加模型分数，必须注明其来源与是否经过独立校准。

未来可以增加 `classifyPage`、`selectUploadInput` 等原子问题，但不让首期接口承担整个发布计划。

## 5. 观察与执行边界

### 5.1 候选收集

- 收集可见、可编辑的文本框和 contenteditable；排除密码框、搜索框、导航区域及无关弹窗。
- 使用 label、aria-label、placeholder、相邻小范围文案和编辑区域归属；不上传整个 DOM。
- 候选上限初始为 20，每个文本属性上限 120 字符；超限需要确定性缩小到编辑区，仍超限则停止，不随意截取前 20 个。
- 初始总输入预算为 4,000 tokens；使用运行时分词能力核对，做不到精确核对时记录估算，并以请求上下文限制兜底。
- open shadow DOM 与同源 frame 按实际支持收集；跨域 frame 需要独立授权和执行路径，不冒充同源访问。
- closed shadow DOM 只走现有经验证的平台桥接。桥接缺失返回 `UNSUPPORTED_SURFACE`，不使用截图或弱匹配掩盖。

### 5.2 引用校验

候选引用表保留在执行上下文，不写到 DOM 属性，也不持久化 Element。每次执行校验：

1. 标签页、frame、document 与观察一致。
2. 节点仍连接、可见、可编辑、未禁用。
3. 标签和结构特征仍与观察一致。
4. 页面导航、编辑区域替换或上下文失效时，废弃整份观察。

不因无关动画或其他页面区域变化就重建全部候选。目标失效时最多重新观察并决策一次，仍失败转人工。

### 5.3 填写与核验

- 模型仅选择目标；待填标题始终来自锁定的任务内容版本和现有平台转换规则。
- 核验目标已有内容；与预期相同则不重复填写，存在不同非空内容时请求用户确认覆盖。
- 使用正确的原生 setter/受支持编辑器写入方式和事件，禁止先清空未知编辑器再试探。
- 填写后等待编辑状态稳定，回读并比较；保留文字和标点，规范化仅限明确的换行表示差异。
- 写入发生后若取消，不重复执行或宣称已回滚。先核对实际状态，再提示用户手动处理。
- 因平台组件不支持可靠回读而无法核验时，结果为待人工确认，不是成功。

## 6. 本地模型接入

### 首选配置

- 开发验证使用 Ollama 本机服务。
- Qwen3 4B 作为中文基线；xLAM-2 3B 与 Granite 3.3 2B 作为对照。
- 验证时固定模型版本/内容摘要、量化、聊天模板、运行时版本、上下文与采样设置。报告记录实际参数，不能只写模型昵称。
- 根据运行时能力使用枚举 JSON Schema/约束解码；并始终做应用层验证。
- 首期只输出选择，不需要通用函数调用框架。不能默认每个候选模型都支持同一种约束格式。
- 日常定位优先非思考模式（仅在所选模型与运行时支持时），测试质量与延迟后再决定。

### 连接与信任

由扩展可信控制上下文发起请求，而非目标网站 MAIN world。Ollama 如需配置扩展来源，仅允许实际扩展来源；不使用通配 CORS、不暴露服务到公网。

默认端点使用 `http://127.0.0.1:11434`。试点只允许回环地址和指定 API 路径；不接受页面提供的服务地址或重定向到远程主机。探测失败明确显示“本地模型未连接”，不静默切云端。

首次启用明确说明模型下载、内存、耗电和本机服务安装要求。连接探测与模型下载需要用户动作；扩展不自行安装系统服务。不能保证 CPU-only 延迟或手机兼容。

### Jev Provider

仅作为未来可选后端，不属于首期。公开资料已确认 API 接入，但未确认本地权重或自托管方式。云端接入必须单独获得页面数据传输授权；不作为本地失败后的默认回退。

## 7. 状态、预算和防止误提交

试点状态：

```text
legacy_locating
  -> observing -> deciding -> validating -> filling -> verifying
                    |            |                      |
                    v            v                      v
                 no_match   stale_observation      verified / needs_review
                                  |
                         最多一次重新观察

任意阶段：failed / cancelled / needs_review
```

首期建议预算，属于待评测配置而非性能承诺：

| 项目 | 初始值 |
| --- | --- |
| 单次模型请求 | 20 秒 |
| 模型请求次数 | 最多 2 次，仅失效观察允许第二次 |
| 候选定位阶段 | 总计最多 45 秒，含观察与请求 |
| 字段核验 | 最多 5 秒 |
| 同一任务、平台、字段 | 同时最多 1 个执行 |

网络超时、非法输出和服务不可用默认直接转人工，不无限重试。请求取消使用中止信号；返回后执行前再次检查取消标记，不能假设中止客户端请求已经停止服务端推理。

首期 Agent 试点作为明确独立的 opt-in 模式：

- 提示“此模式只辅助填充，最后由你在平台确认发布”。
- 试点任务强制禁止自动提交，包括旧适配器的提交分支；即使本次未用模型也一样。
- 开关关闭时保持原来的执行模式，不全局改变所有平台的自动发布行为。
- 确认账号与内容在人工预览环节完成；未能确定账号时明确提示，不推断账号正确。

结果只声明 `verified` / `no_match` / `needs_review` / `failed` / `cancelled`。`verified` 仅指目标字段核验完成，不等于整篇已填充或发布成功。平台的整体结果仍需要所有必要步骤完成。

## 8. 生命周期与素材

首期决策不是后台内存中的不可恢复长循环：

- 在有界阶段的开始和结束持久化任务 ID、内容版本、平台、阶段、执行器实例 ID 和结果；不保存 DOM 引用或页面全文。
- 扩展重启后未完成阶段转为 `needs_review`，重新观察实际字段，不自动重放填写或提交。
- 页面导航或关闭时显式停止该执行；锁由当前执行器所有权和存活状态核对释放，不仅依靠过期时间。
- 多编辑窗口的待发布内容不能靠全局单个快照混用；试点任务绑定独立快照 ID。
- 第一期仅操作已有上传完成的标题字段，不为模型传递 Blob。

跨设备版本再引入稳定 `assetId` 和 IndexedDB/文件存储。手机不能使用电脑的 `blob:` URL；这属于后续素材层改造，不是本次定位试点的前置大工程。

## 9. UI、日志与错误

设置提供：试点开关、本地连接状态、模型选择/版本信息、连接测试和数据说明。

任务显示：正在观察、正在本地判断、正在核验；支持停止和跳到平台手动处理。关闭试点后不再发起新模型请求；已有操作按取消语义收尾。

错误使用明确代码和可理解说明：

- `MODEL_UNAVAILABLE`：检查本地服务与模型。
- `DECISION_TIMEOUT`：停止自动辅助，手动填写。
- `INVALID_DECISION`：记录 Provider/版本信息，不擅自执行。
- `NO_MATCH`：未找到合适标题框。
- `STALE_OBSERVATION`：刷新观察后仍无法锁定目标。
- `UNSUPPORTED_SURFACE`：页面区域无法在当前权限下读取。
- `VERIFY_FAILED`：填写后的内容未核验通过。

默认日志只记录耗时、数量、版本、状态与错误码。默认不存正文、截图、账号名、令牌或原始 DOM。用户可以单独同意生成脱敏诊断包；采集训练数据是另一项授权，不捆绑在启用功能中。

## 10. 拟议代码边界

实施时逐步新增，不在方案阶段创建空目录或引入新依赖：

| 模块 | 拟议职责 |
| --- | --- |
| `src/agent/types.ts` | 无 Chrome 依赖的观察、请求和结果契约 |
| `src/agent/decision.ts` | 有限选择、输出验证和 Provider 接口 |
| `src/agent/ollama.ts` | 本地端点、请求、超时、模型响应适配 |
| `src/agent/controller.ts` | 有界定位、取消和核验流程 |
| `src/contents/agent-observer.ts` | 浏览器观察、引用表和受控字段操作 |
| 现有小红书适配与桥接 | 调用定位辅助，不直接包含模型请求 |
| 现有后台与侧边栏 | 任务锁、状态保存、用户开关和错误展示 |

实施前核实 Plasmo 对 content script 入口和消息通信的约定。MAIN world 桥接只暴露最小操作，消息校验来源、类型、ID 和待处理任务；不要将窗口消息当成可信授权。写权限由可信控制器判断。

由于函数注入不会携带 import，新增能力通过打包后的 content script 和类型化消息调用，而不是继续把依赖模块的函数序列化注入。

## 11. 实施阶段与交付物

### P0：执行基础与试点边界

- 复现真实小红书注入路径，解决试点闭包依赖和加载等待。
- 加入试点模式与强制不自动提交的执行约束。
- 定义任务版本、锁、阶段结果和取消语义。
- 用现有稳定定位路径验证“填写后核验”，避免先把核验问题误归咎于模型。

退出条件：普通路径、取消和重试可验证，试点绝不会调用提交动作。

### P1：本地语义定位最小闭环

- 实现候选观察、有限选择、本地 Provider 和安全填写。
- 支持 `none`、服务不可用、非法输出、观察失效和人工接管。
- 在标题定位失败时触发，不修改上传和其他平台流程。

退出条件：受控页面改版夹具与用户授权的真实账号填写验证通过。

### P2：对照评测与有限扩展

- 比较本地模型、固定规则与现有启发式基线。
- 满足验收后才扩展正文定位、页面分类；分别建立独立测试集。
- 复杂富文本和上传保留专用工具，不直接由模型写任意代码。

### P3：产品化与跨平台

- 若本机服务安装门槛确实阻碍用户，再评估桌面 App + llama.cpp 随应用管理推理进程。
- 手机先作为内容工作台和控制端；官方 API、桌面执行器和系统分享各走各的权限边界。
- 有审核数据后评估 FunctionGemma/分类器微调；不从零训练 Jev 类基础模型。

本方案不承诺工期。P0/P1 的真实页面可观察性、模型硬件条件和编辑器回读能力，是是否继续扩展的决策门槛。

## 12. 验证与发布门槛

### 自动化测试

使用现有 Vitest，新增观察夹具、Provider mock 与控制器测试。至少覆盖：

- 标签/占位符改名、DOM 包装变化、控件重排。
- 多个相似输入框、隐藏框、弹窗、只有正文框、无标题框。
- open shadow DOM、同源 frame 和不支持的区域。
- 观察后节点替换、导航、用户改写、任务取消和扩展恢复。
- 模型超时、非法 JSON、未知 ID、`none`、失效返回和回环端点校验。
- 页面包含诱导指令时，不能增加候选外动作、外发数据或触发提交。
- 回读不一致、异步值回退、重复启动和自动发布配置为 true。

### 模型离线评测

建立不少于 100 个独立标注场景，其中至少 30 个无匹配/歧义/不可操作场景。按布局族和页面版本分组留出测试，避免同一 DOM 小改动同时进入训练与测试。

报告逐项列出：

- 唯一可解场景的选择正确率、错误选择数、拒绝数。
- 不可解场景的错误执行率与正确接管率。
- 核验后的正确填写率；不能只统计合法 JSON。
- 每种模型的冷启动、热请求 p50/p95、超时率、峰值内存。
- 测试硬件、样本分布、模型量化和运行时版本。
- 与既有定位方式的结果对比，确认收益来自变化场景，而非只在正常页成功。

初始功能门槛：唯一可解场景选择正确率至少 95%；测试集中无错误字段写入、无无匹配场景写入、无任何 Agent 自动提交。另设性能门槛：目标硬件热请求 p95 不超过 10 秒，超时仍按既定预算接管。数字是验收目标，不是已有实测结果。

小样本中的零错误不代表真实零风险。未达门槛不提高权限或降低核验要求，应缩小范围、改进观察或换模型。

### 真实平台与回归

- 用户授权后在实际平台做只填充、不提交的冒烟验证；无需发布内容就能验证首期目标。
- 常规路径、故意使固定定位失败的受控测试路径均需验证。
- 运行 `pnpm test`、`pnpm typecheck`、相关文件检查和扩展构建，并检查实际打包后的注入/消息链。
- 全平台自动发布行为保持原样，只有明确启用的试点任务执行不提交策略。

真实平台环境无法验证时，只能报告夹具/单测通过，不能标记试点已经可用。

## 13. 主要风险与降级策略

| 风险 | 策略 |
| --- | --- |
| 模型选错合法候选 | 候选缩小、`none`、执行前检查、回读核验、必要时人工接管 |
| 页面不可观察 | 明确不支持，保留专用适配与人工流程 |
| 本地模型太慢/太大 | 规则优先、较小模型、有限输入；不默认切云端 |
| 网页提示注入 | 页面作为不可信数据；受控工具和代码权限独立于模型 |
| 用户已有内容被覆盖 | 非空冲突确认，任务内容版本锁定 |
| 超时后旧操作仍进行 | 单次执行锁、取消前后校验、重试前核对实际状态 |
| 平台条款或权限变化 | 停止适配，提示限制；模型不绕过限制 |
